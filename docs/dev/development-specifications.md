## Implementation order

1. Establish the client/server workspace layout, environment configuration, shared domain types, and API error contract.
2. Add PostgreSQL migrations and workspace-scoped task endpoints.
3. Implement the task list and Smart Input using the optimistic mutation contract.
4. Add IndexedDB persistence, offline mutation handling, and failure recovery.
5. Add authentication, workspace membership enforcement, and task views/search.
6. Add the command palette and keyboard shortcuts.
7. Add the AI queue, breakdown endpoint, preview modal, and acceptance flow.
8. Run the release gates in [security-accessibility-and-performance.md](security-accessibility-and-performance.md).

## Decisions and assumptions

- V1 uses workspace-scoped REST resources. The active workspace is explicit in the URL so cache keys and authorization boundaries are unambiguous.
- The server is authoritative. Optimistic UI changes are temporary client projections and must reconcile with the server response.
- UUIDs are generated by the client for optimistic task creation and accepted by the API. This makes the optimistic item addressable before the request completes.
- A mutation is retried automatically only for network/5xx failures. Validation and authorization failures roll back immediately.
- AI generation is P1. The task list and ordinary task creation remain fully usable if the AI provider or Redis is unavailable.
- OAuth provider details are implementation work, but the client contract remains HTTP-only session cookies; access tokens must not be stored in browser storage.
